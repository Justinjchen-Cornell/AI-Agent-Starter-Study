# 第 2 课：prompt/prompts.yml —— 给 Agent 写"人设"和"家规"

> **本节目标**：看懂系统提示词（system_prompt）怎么写、如何约束 Agent 行为
> **预计时长**：25 分钟 ｜ **前置**：完成第 1 课，最好已启动过项目

## 先解悬念

启动项目时终端刷出来的两大段"字典"，就是这个文件的全部内容（第一段 = `main_agent`，第二段 = 三个子智能体）。今天去它的老家看看。

**使命一句话**：用纯文字告诉 AI——**你是谁、有哪些手下、按什么规矩干活**。

## ① 先认识 YAML 格式

```yaml
main_agent:                  # 大标题
  system_prompt: |           # 缩进两格 = 属于 main_agent 名下
    你是一个空调公司的智能团队负责人……
```

- `.yml` = 一种**配置文件格式**：纯文本、靠**缩进**分层次、竖线符号表示"下面是一大段多行文字"
- 为什么不用 Python 写提示词？因为这样**改提示词不用懂代码**——产品、运营、你都能改；改完重启即生效

## ② 提示词三件套（主智能体部分）

### 1）角色设定（你是谁）

```
你是一个空调公司的智能团队负责人，负责协调三个专家助手完成复杂任务
你的团队成员如下：
  1. **网络搜索助手**  2. **数据库查询助手**  3. **RAGFlow助手**
```

给大模型戴"**角色帽子**"。模型本身是"什么都聊的通才"，这段话让它入戏成有职责、有手下、有目标的团队负责人。类比：新员工第一天的《岗位说明书》。

### 2）工作流程（怎么干）

```
对于背景知识和外部知识 → 网络搜索助手
对于企业内部专有知识 → RAGFlow助手
对于商品数据       → 数据库查询助手
```

给 AI 一张"**决策地图**"——什么情况叫哪个手下。没有它，AI 可能拿锤子当万能工具。

### 3）红线条款（绝对不许）

```
【关键执行顺序】
1. 必须先调用子智能体获取信息
2. **绝不允许**在获取信息之前调用文件生成工具
3. 严禁使用"等待子任务完成"之类的占位符内容生成文件
4. 先搜索再生成要分两步，不要在同一个 Tool Call 里同时做
```

**给 AI 立规矩**。为什么语气这么重（必须/绝不）？因为大模型有两个"天性"：**爱抢答**（没查资料就先编）和**爱偷懒**（用占位符糊弄）。写提示词有一半工作是在"修补天性"。第 4 条尤其有意思——这明显是作者**被坑过之后**总结的经验，写进了家规。

## ③ 子智能体们的提示词——各有各的 KPI

```yaml
tavily:  ……至少检索3个角度……一共最多进行5次检索……
ragflow: ……至少提问三个不同的问题
         保留检索的全部信息，不需要进行概括性总结……
```

两个精妙设计：

- **数字约束**（至少 3 / 最多 5）：定 KPI + 定上限——保质量的同时，防止"无限搜索"烧钱烧时间
- **信息保真原则**（"保留全部信息，不要概括"）：子智能体只负责**搬砖**不负责**装修**——原始信息原样交给主智能体，避免层层摘要丢细节

> 🤫 彩蛋：仔细读会发现提示词里有处小矛盾——文中提到"文件生成助手"，但团队名单里只有三个助手、并没有它。**现实世界的提示词也会"写飘"**，这正是提示词工程是一门手艺的原因。也许你会是第一个修复它的人。

## 📌 概念卡

| 概念 | 一句话 |
|------|--------|
| system_prompt | AI 的"岗位说明书 + 员工手册"：是谁、听谁、不许干嘛 |
| YAML | 不写代码就能改的配置：缩进分层，竖线写大段文字 |
| 硬约束 | "必须/绝不 + 数字上限"，修补模型的抢答/偷懒天性 |
| 配置与代码分离 | 改人设不改代码——本项目最妙的设计之一 |

## ✍️ 复述题

1. 用"员工手册"的比喻说说：system_prompt 到底在干什么？
2. "最多进行 5 次检索"这种硬数字是干嘛的？不加会发生什么？
3. 想把它改成"水果电商公司"助手，你改哪个文件、动哪几处？

<details>
<summary>💡 参考答案</summary>

1. system_prompt 就像给 AI 发的员工手册：先定义它的岗位（角色），再写清楚工作流程（遇什么事找谁/怎么做），最后定红线（绝对不许做什么）。它不改变模型的能力，而是改变模型的"身份感"和"行为习惯"。
2. 数字约束 = 给 AI 定 KPI 和预算上限。不加的话，子智能体可能搜两三下就停（质量不够），也可能无限搜下去（烧钱烧时间）。人类团队管理里的"目标 + 上限"思路，直接搬过来用。
3. 改 `prompt/prompts.yml`：把主智能体的"空调公司"角色改掉、工作流程按水果电商的业务改写；子智能体的名字/描述/提示词按需调整。全程不用改 Python 代码。

</details>

## 🎁 动手实验（2 分钟）

1. 打开 `prompt/prompts.yml`，把开头的"**空调公司**"改成你喜欢的场景
2. 保存 → 重启服务器
3. 观察启动打印的第一段字典：公司名已经变了——**改一行文字，AI 的"身份"立即更新**
4. 玩够了改回来，或留着看它干活时怎么自称
